HTTP field guide · Read the exchange

HTTP is a conversation. Learn to read it.

Follow a request from its method and headers to the response it earns. Learn what HTTP promises, what intermediaries can change, and how HTTP/1.1, HTTP/2 and HTTP/3 carry the same semantics in different ways.

Work through real exchanges, test your reasoning, and finish each level with a paper-based concept lab—not a generic coding project.

ONE HTTP EXCHANGE HTTP/1.1
REQUEST 
GET /orders?limit=10 HTTP/1.1
Host: api.example.test
Accept: application/json
RESPONSE 
HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: max-age=60

{"items":[],"next":null}

Read the contract: the method says what the client wants; the status and fields say how the server handled it.

HTTP/1.1Text messages over a TCP connection
HTTP/2Compressed fields and multiplexed binary frames
HTTP/3HTTP frames carried over QUIC streams

Examples follow RFC 9110 to RFC 9114. Messages are pre-written and hand-checked; nothing is sent over a network. Line endings are shown as plain newlines (on the wire each ends in CRLF), and timings are illustrative. Behaviour that differs between implementations is labelled.
